# 04 — MODEL / построить модели

[Английская версия](04-model.md)

## Вопрос

Какое поведение, данные и контракты теперь необходимо сделать явными?

Владение достаточно стабильно, чтобы детализировать зависящие от него знания.

## Бизнес-поведение

`BR-01` — Экспорт не должен изменять исходный документ.

`BR-02` — Каждый выбранный лист обрабатывается независимо.

`BR-03` — Ошибка одного листа не должна удалять уже успешно сформированные PDF.

`BR-04` — После обработки всех выбранных листов пользователь получает итоговый результат.

## Модель состояния плагина

```text
Idle
  ↓
Preparing
  ↓
Exporting
  ↓
WritingManifest
  ↓
Completed
```

Ошибка отдельного листа не переводит всё задание непосредственно в общий терминальный отказ.

Результат задания:

```text
SUCCESS
PARTIAL_SUCCESS
FAILED
```

## Контракт хоста

Концептуально:

```text
getSelectedSheets()
getDocumentIdentity()
exportSheetToPdf(sheetId, targetPath)
```

Точный API намеренно не задаётся.

## Контракт файловой системы

Концептуально:

```text
ensureOutputDirectory(path)
writeFile(path, bytes)
writeManifest(path, json)
```

Это описание ответственности, а не реальный API операционной системы.

## Модель манифеста

```json
{
  "sourceDocumentId": "DOC-42",
  "exportedAt": "2030-01-01T10:00:00Z",
  "outputDirectory": "/exports/project-a",
  "items": [
    {
      "sheetId": "A101",
      "sheetName": "Floor Plan",
      "fileName": "A101-Floor-Plan.pdf",
      "status": "SUCCESS"
    }
  ]
}
```

JSON является иллюстративным.

## Оставшиеся открытые вопросы

`OPEN-01` — политика конфликта существующего файла остаётся нерешённой.

`OPEN-02` и `OPEN-03` относятся к реализации и не блокируют концептуальный базовая версия.

## Результат

Поведение и интерфейсы детализированы **после определения владения**, а не раньше.
