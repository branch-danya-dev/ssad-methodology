# 02 — BOUND / определить границы

[Английская версия](02-bound.md)

## Вопрос

Какую систему мы анализируем?

## Анализируемая система

В этом пример анализируется:

> **Решение Sheet Export Plugin**, ответственное за оркестрацию экспорта выбранных листов документа хоста в локальные файлы PDF и формирование результата операции.

Сам плагин является главным внутренним компонентом времени выполнения.

Приложение-хост и файловая система находятся за границей логики плагина, но являются авторитетными внешними средами, существенно влияющими на решение, поэтому получают отдельные аналитические перспективы.

## В области анализа

```text
использование выбранных листов
оркестрация экспорта
обработка результата каждого листа
создание манифеста
работа с директорией назначения
взаимодействие с экспортом приложения-хоста
взаимодействие с локальной файловой системой
формирование итогового результата плагина
```

## Вне области анализа

```text
редактирование документ CADа
внутренний движок отрисовки приложения-хоста
реализация файловой системы ОС
аутентификация пользователя
облачная синхронизация
удалённое хранилище
системы управления документами
сетевой транспорт
```

## Модель границ

```text
Пользователь
    │
    ▼
[ Sheet Export Plugin ]
    │          │
    │          └──────────────► Локальная файловая система
    │
    └─────────────────────────► приложение-хост CAD
```

Авторитетность:

```text
Плагин
→ владеет оркестрацией и интерпретацией результата

Приложение-хост
→ владеет состоянием исходного документа и возможностью экспорта

Файловая система
→ владеет физическим сохранением сформированных файлов
```

## Следствие для перспектив

Граница обосновывает:

```text
business/
plugin/
host-application/
filesystem/
system/
```

Она не обосновывает:

```text
backend/
frontend/
database/
integrations/
```

Общая область `integrations/` намеренно отсутствует в исходной версии.
