# 06 — SYNTHESIZE / выполнить системный синтез

[Английская версия](06-synthesize.md)

## Вопрос

Какое знание относится ко всей системе, а не к одному владельцу?

Основные перспективы уже достаточно понятны, чтобы собрать системное представление.

## Контекст системы

```text
          Пользователь
              │
              ▼
     [ Sheet Export Plugin ]
         │             │
         │             ▼
         │      Локальная файловая система
         │
         ▼
приложение-хост CAD
```

## Сквозной сценарий

```text
1. Пользователь выбирает листы в документе хоста.
2. Плагин читает текущий выбор.
3. Плагин получает идентичность исходного документа.
4. Плагин создаёт задание экспорта.
5. Для каждого выбранного листа:
   a. формирует имя файла;
   b. запрашивает экспорт PDF у хоста;
   c. фиксирует SUCCESS или FAILED.
6. Плагин формирует манифест.
7. Файловая система сохраняет манифест.
8. Плагин определяет общий результат:
   SUCCESS / PARTIAL_SUCCESS / FAILED.
9. Пользователь получает итог.
```

## Системные инварианты

`SI-01` — Содержимое исходного документа не изменяется заданием экспорта.

`SI-02` — Для каждого выбранного листа в итоговом манифесте существует ровно одна запись.

`SI-03` — Успешно сформированный PDF другого листа не удаляется из-за последующей ошибки.

`SI-04` — Общий `SUCCESS` возможен только тогда, когда успешны все листы.

`SI-05` — Общий `FAILED` означает, что ни один лист не был успешно экспортирован.

## Почему это принадлежит `system/`

Ни одна перспектива не владеет всеми участвующими фактами:

```text
BR-02
+
оркестрация плагина
+
экспорт хоста
+
сохранение файлов
=
SI-03
```

Поэтому инвариант синтезируется у ближайшего общего системного владельца.

## Результат

Система теперь понятна от начала до конца без дублирования компонентных деталей.
