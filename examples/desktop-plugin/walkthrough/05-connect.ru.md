# 05 — CONNECT / связать знания

[Английская версия](05-connect.md)

## Вопрос

Как локальные модели соединяются в навигационный граф знаний?

На этом этапе SSAD не создаёт новых владельцев. Связываются уже принадлежащие кому-то знания.

## Трассируемость

```text
BR-01
Исходный документ нельзя изменять
    ↓
plugin/
оркестрация экспорта использует только операции чтения и экспорта хоста
    ↓
host-application/
контракт экспорта не должен требовать изменения документа
    ↓
verification
состояние исходного документа сравнивается до и после экспорта
```

```text
BR-02
Каждый выбранный лист обрабатывается независимо
    ↓
plugin/
цикл по листам + отдельный результат листа
    ↓
filesystem/
успешные результаты сохраняются
    ↓
system/
частичный успех является допустимым итогом задания
```

## Связи владения

```text
Идентичность листа у хоста
    ↓ используется
Оркестрацией плагина
    ↓ записывается в
Содержание манифеста, которым владеет плагин
    ↓ физически сохраняется
Файловой системой
```

## Технология и ответственность

На этом этапе отдельный технологический документ не нужен.

В пример есть концептуальные ответственности:

```text
возможность экспорта хоста
сохранение в файловой системе
JSON-манифест
```

но значимых технологических решений сверх предпосылок сценария ещё нет.

SSAD не должна придумывать `stack/` только ради ощущения полноты.

## Следствие для навигации

В стабильном репозитории появятся связи вида:

```text
business/BR-02
→ plugin/поведение по листам
→ filesystem/сохранение результатов
→ system/инвариант частичного успеха
```

Физическое дерево остаётся иерархичным, а отношения образуют граф знаний.

## Результат

Локальные модели теперь объясняют не только **что** знает каждый владелец, но и **зачем** это знание существует и от чего зависит.
