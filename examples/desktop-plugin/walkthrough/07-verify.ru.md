# 07 — VERIFY / проверить

[Английская версия](07-verify.md)

## Вопрос

Согласуются ли перспективы между собой и с заданными предпосылками сценария?

## Матрица проверки

| Проверка | Результат |
|---|---|
| `E-08` исходный документ неизменен ↔ `BR-01` | PASS |
| `BR-02` независимая обработка ↔ состояние плагина | PASS |
| владение манифестом плагином ↔ физическое хранение | PASS |
| статусы листов ↔ общий результат системы | PASS |
| отсутствие сетевой зависимости ↔ набор перспектив | PASS |
| системные инварианты ↔ локальное поведение владельцев | PASS |

## Обнаруженное противоречие

Во время проверки `OPEN-01` становится значимым:

> Что происходит, если целевой PDF уже существует?

Без политики конфликта файлов поведение файловой системы может противоречить `BR-03`.

Например:

```text
существующий A101.pdf
+
новый экспорт A101 завершается ошибкой после замены файла
=
пользователь может потерять ранее корректный результат
```

## Возврат к исходному знанию

Проблема возвращает анализ к бизнес-поведению и ожиданиям от файловой системы.

Решение сценария:

`OPEN-01 → DECIDED`

```text
Существующие файлы не перезаписываются молча.

При конфликте плагин должен:
1. получить явное подтверждение перезаписи до экспорта; или
2. выбрать свободное имя.

Неудачный экспорт не должен уничтожать существующий файл.
```

Появляется:

`BR-05` — Существующие результаты не должны разрушительно перезаписываться без явного согласия пользователя.

И:

`SI-06` — Ошибка экспорта не должна уменьшать множество корректных ранее существовавших выходных файлов.

## Почему это важно

Разбор процесса намеренно не является идеально линейной цепочкой.

`VERIFY` обнаружил отсутствующее исходное правило и вернул анализ назад.

Это ожидаемое поведение SSAD.
