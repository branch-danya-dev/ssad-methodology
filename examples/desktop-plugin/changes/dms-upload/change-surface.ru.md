# область влияния изменения — загрузка в СЭД

[Английская версия](change-surface.md)

## Первый проход

| Перспектива / вопрос | Влияние | Причина |
|---|---|---|
| Бизнес-перспектива | ДА | загрузка становится наблюдаемым пользовательским поведением |
| Граница системы | ДА | появляется внешняя СЭД |
| Плагин | ДА | появляется оркестрация загрузки и локальный статус |
| Приложение-хост | НЕТ | ответственность экспорта хоста не меняется |
| Файловая система | ДА | манифест начинает хранить статус загрузки |
| Интеграции | ДА / НОВАЯ | появляется межсистемный контракт СЭД |
| Владение данными | ДА | локальный статус загрузки и удалённое состояние необходимо разделить |
| Доверие / безопасность | ДА | появляется внешняя аутентификация и удалённая авторитетность |
| Отказы / восстановление | ДА | локальный успех может сочетаться с ошибкой загрузки |
| Приёмка | ДА | результаты загрузки должны быть наблюдаемы |
| Трассируемость | ДА | новое поведение должно связываться с интеграцией и моделью статусов |

## Вопросы границы

```text
Появляется новая внешняя система?
→ ДА

Перемещается владение исходным документом?
→ НЕТ

Становится ли СЭД владельцем локального PDF?
→ НЕТ
Локальный файл остаётся локальным результатом экспорта.

Становится ли СЭД авторитетным источником существования удалённого документа?
→ ДА
```

## Вопросы владения

Новое знание:

```text
Намерение загрузки / локальный статус
→ Плагин

Физический локальный PDF
→ Файловая система

Удалённый идентификатор / существование документа
→ СЭД

Запрос, аутентификация, повторы и согласование через границу
→ integrations/dms/

Смысл сочетания локального успеха и удалённой ошибки
→ system/
```

## Ключевой вывод

Наивное описание реализации могло бы выглядеть так:

```text
Плагин
→ POST /documents
```

SSAD сначала показывает более глубокое изменение:

```text
новый авторитетный источник
+
новый сценарий отказа
+
новая граница доверия
+
новое состояние данных
+
новое поведение приёмки
```

Именно это является реальной областью влияния изменения.
