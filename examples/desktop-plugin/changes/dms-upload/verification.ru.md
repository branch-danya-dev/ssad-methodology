# Проверка изменения — загрузка в СЭД

[Английская версия](verification.md)

## Вопросы проверки

### Уничтожает ли ошибка СЭД локальный успех?

Ожидаемый ответ: **НЕТ**

`BR-07` и исходные правила файловой системы требуют сохранить локальный результат.

### Становится ли СЭД авторитетным источником локального успеха экспорта?

Ожидаемый ответ: **НЕТ**

СЭД является авторитетной только для состояния удалённого документа.

### Может ли плагин записать `UPLOADED` после неоднозначного тайм-аута?

Ожидаемый ответ: **НЕТ**

Неоднозначный тайм-аут требует согласования с внешней СЭД согласно её контракту.

### Можно ли загружать неудачно экспортированный лист?

Ожидаемый ответ: **НЕТ**

Это запрещено `BR-06`.

### Требуется ли изменение приложения-хоста?

Ожидаемый ответ: **НЕТ**

Изменение СЭД находится после успешного локального экспорта.

## Новые системные инварианты

`SI-07` — Ошибка удалённой загрузки никогда не удаляет и не делает недействительным успешно сформированный локальный PDF.

`SI-08` — `UPLOADED` фиксируется только после подтверждённого удалённого успеха или успешного согласования состояния.

`SI-09` — Элемент с неудачным локальным экспортом не может перейти к выполнению загрузки.

`SI-10` — Удалённая идентичность документа является авторитетной только внутри границы СЭД.

## Трассируемость

```text
BR-07
    ↓
состояние загрузки у плагина
    ↓
сохранение локального файла
    ↓
поведение интеграции при отказе
    ↓
SI-07
    ↓
приёмка: локальный PDF остаётся после ошибки загрузки
```

## Результат

Изменение может двигаться к новому Stable после того, как:

- выбран конкретный контракт СЭД;
- определён механизм аутентификации;
- идемпотентность и согласование проверены относительно выбранного провайдера;
- обновлены затронутые документы базовая версия.

Синтетический пример намеренно останавливается до выдумывания специфических фактов провайдера.
