## Запрос на изменение

> После локального экспорта позволить пользователю загружать успешно сформированные PDF во внешнюю систему управления документами.

## Почему это не просто задача плагина

Исходная граница:

```text
Плагин
├── Приложение-хост
└── Локальная файловая система
```

Новый сценарий добавляет:

```text
Плагин
└── Внешняя СЭД
```

Следовательно, меняется граница системы.

Изменение необходимо проанализировать до проектирования конкретного API или SDK.

## Процесс изменения

1. [`change-surface.ru.md`](change-surface.ru.md) — определить затронутых владельцев.
2. [`impact-analysis.ru.md`](impact-analysis.ru.md) — определить необходимые изменения знаний.
3. [`verification.ru.md`](verification.ru.md) — проверить авторитетность, отказы и трассируемость.

## Изменение структуры

До:

```text
business/
plugin/
host-application/
filesystem/
system/
```

После:

```text
business/
plugin/
host-application/
filesystem/
integrations/
  dms/
system/
```

Новая перспектива `integrations/` появляется **потому, что её обосновывает изменившаяся архитектура**.

Она не создавалась заранее как пустая директория ради методологии.
