# Example — мобильное приложение

[Английская версия](README.md)

> **Статус:** синтетический пример  
> **Назначение:** показать владение локальными и серверными данными и границы синхронизации.

## Сценарий

Вымышленное мобильное приложение для личных финансов позволяет пользователю записывать расходы без сети и при необходимости синхронизировать их между устройствами после входа в учётную запись.

Допущения:

```text
мобильный клиент
серверный API
локальная SQLite
серверная PostgreSQL
внешний провайдер идентификации
```

## Пример владения

```text
рабочая локальная запись расхода
→ клиент во время автономной работы

синхронизированное состояние расходов учётной записи
→ сервер после синхронизации

подтверждение личности
→ внешний провайдер идентификации

решение о доступе к функциям продукта
→ сервер приложения
```

Пример заставляет разделить:

```text
идентичность у внешнего провайдера
≠
авторитетное решение приложения

локальное рабочее состояние
≠
синхронизированное серверное состояние
```

## Пример области влияния изменения

Запрос:

> Разрешить членам одной семьи совместно вести книгу расходов.

Вероятная область влияния:

```text
Бизнес                  ДА
Граница системы         ДА
Владение данными        ДА
Серверная часть         ДА
Клиент                  ДА
Интеграция идентификации ДА
Доверие / авторизация   ДА
Модель отказов          ДА
Приёмка                  ДА
```

Это не просто функция клиентского приложения, потому что меняются владение и авторитетность.

## Намеренные упрощения

Пример не утверждает существование реального набора API, схемы БД, протокола аутентификации или репозитория реализации.
