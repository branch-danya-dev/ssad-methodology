# Синтетические примеры

[Английская версия](README.md)

В этой директории находятся **вымышленные или намеренно упрощённые системы**, используемые для объяснения SSAD.

Примеры не утверждают, что описанный продукт, код, инфраструктура или реализация существуют в действительности.

## Глубина пример

Пример может быть:

```text
точечным
→ показывает один или два принципа методологии

полным
→ проходит существенную часть workflow
→ показывает и построение, и стабильное владение знаниями
→ может включать разбор изменения системы
```

## Текущие примеры

| Пример | Форма | Основная тема | Глубина |
|---|---|---|---|
| [Мобильное приложение](mobile-application/) | клиент + сервер + локальное/серверное хранение | владение данными и синхронизация | точечный |
| [Настольный плагин](desktop-plugin/) | плагин + приложение-хост + файловая система | рабочий процесс → базовая версия → изменение | **полный** |
| [Событийная платформа](event-driven-platform/) | сервисы + сообщения + данные + эксплуатация | распределённое владение и асинхронные контракты | точечный |

## Рекомендуемый полный пример

Начинать лучше с [`desktop-plugin/`](desktop-plugin/).

В нём намеренно разделены:

```text
walkthrough/
→ временная последовательность анализа

baseline/
→ стабильные знания, организованные по системе

changes/
→ развитие после стабилизации
```

Эта структура принадлежит **учебному примеру**, а не самой анализируемой системе.

Стабильная документация внутри `baseline/` организована по реальным владельцам:

```text
business/
plugin/
host-application/
filesystem/
system/
```

Это различие является намеренным и принципиально важным для SSAD.

## Правила для примеры

Каждый пример должен по возможности указывать назначение, допущения, форму системы, аналитические перспективы, модель владения, демонстрируемый принцип SSAD и намеренные упрощения.

Пример не должен представляться как подтверждение реальной реализации.
