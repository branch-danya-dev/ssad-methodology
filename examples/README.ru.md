# Синтетические примеры

[Английская версия](README.md)

В этой директории находятся **вымышленные или намеренно упрощённые системы**, используемые для объяснения SSAD.

Examples являются учебными и исследовательскими материалами. Они не утверждают, что описанный продукт, код, инфраструктура или реализация существуют в действительности.

## Зачем нужны синтетические примеры

Методология должна показывать своё поведение на разных формах систем без необходимости разрабатывать полноценный реальный проект для каждого вопроса.

Поэтому пример может быть специально сконструирован, чтобы показать:

- систему без серверной части;
- границу с приложением-хостом;
- распределённое владение данными;
- асинхронное взаимодействие;
- внешний авторитетный источник;
- отдельную эксплуатационную перспективу;
- изменение границы системы;
- сложную область влияния изменения.

## Правила для examples

Каждый пример ДОЛЖЕН ПО ВОЗМОЖНОСТИ указывать:

```text
назначение
форму системы
допущения
аналитические перспективы
модель владения
какой принцип SSAD он показывает
какие детали намеренно упрощены
```

Пример НЕ ДОЛЖЕН представляться как подтверждение реальной реализации.

## Текущие примеры

| Пример | Форма | Основная тема |
|---|---|---|
| [Мобильное приложение](mobile-application/) | клиент + сервер + локальное/серверное хранение | владение данными и синхронизация |
| [Настольный плагин](desktop-plugin/) | плагин + приложение-хост + файловая система | граница хоста и нестандартные перспективы |
| [Событийная платформа](event-driven-platform/) | сервисы + сообщения + данные + эксплуатация | распределённое владение и асинхронные контракты |

Примеры намеренно отличаются друг от друга. Их задача — показать, что SSAD следует устройству системы, а не одному универсальному дереву репозитория.
