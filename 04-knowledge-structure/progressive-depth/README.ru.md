# Progressive Depth

SSAD должна позволять читать систему на нужной глубине, не заставляя каждого пользователя проходить весь репозиторий.

## Принцип

```text
SYSTEM OVERVIEW
↓
RESPONSIBILITY AREA
↓
BEHAVIOR / CONTRACT / DATA
↓
TECHNOLOGY
↓
TECHNOLOGY USAGE
↓
IMPLEMENTATION EVIDENCE
```

Чем глубже уровень, тем больше деталей и тем уже аудитория.

## Зачем это нужно

Новому участнику обычно нужен контекст и карта системы. Разработчику конкретного backend-модуля нужен контракт и поведение. Аналитику изменения — ownership, flows и зависимости. QA — состояния, edge cases и failure semantics.

Один и тот же репозиторий должен поддерживать все эти режимы чтения.

## Overview не должен дублировать детали

Верхний уровень отвечает:

- что это за система;
- какие крупные зоны ответственности существуют;
- как они связаны;
- куда идти дальше.

Он не должен копировать локальные контракты и правила целиком.

## Локальная самодостаточность

Документ должен содержать достаточно контекста, чтобы читатель понял локальную тему без открытия десяти соседних файлов, но не превращаться в копию всей системы.

Полезная формула:

```text
LOCAL CONTEXT
+
CANONICAL FACTS OF THIS OWNER
+
LINKS TO FOREIGN KNOWLEDGE
```

## Критерий хорошей структуры

Репозиторий может быть физически большим, но должен **ощущаться маленьким**: в каждый момент пользователь видит только тот слой знания, который нужен для его вопроса.
