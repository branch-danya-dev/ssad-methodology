# Практические сценарии SSAD

[Английская версия](README.md)

Практические сценарии переводят SSAD из уровня методологии в **повторяемую практическую работу аналитика**.

Они отвечают на вопрос:

> **У меня такая исходная ситуация — что делать дальше?**

Практический сценарий не определяет итоговое дерево репозитория. Он задаёт практическую последовательность вопросов, проверок, результатов и контрольных точек.

## Базовые практические сценарии

| Исходная ситуация | Практический сценарий |
|---|---|
| система или подсистема создаётся с нуля | [`new-system.ru.md`](new-system.ru.md) |
| система существует, но знания о ней ненадёжны или разрозненны | [`existing-system.ru.md`](existing-system.ru.md) |
| существует доверенная основа и приходит значимое изменение | [`change.ru.md`](change.ru.md) |

Краткий выбор: [`quick-reference.ru.md`](quick-reference.ru.md)

## Общая форма практического сценария

Каждый практический сценарий содержит:

```text
Когда применять
Исходные данные
Шаги
Ожидаемые результаты
Контрольные точки качества
Условия остановки или возврата
Типичные ошибки
Условия завершения
```

## Практические сценарии и рабочий процесс

Канонический рабочий процесс:

```text
DISCOVER → BOUND → OWN → MODEL → CONNECT → SYNTHESIZE → VERIFY → STABILIZE → EVOLVE
```

Практические сценарии не заменяют его.

Они **выбирают и усиливают те части процесса, которые важны для конкретной исходной ситуации**.

Например:

```text
Новая система
→ больше работы с BOUND и OWN

Существующая система
→ больше DISCOVER и согласования подтверждений

Изменение
→ область влияния + точечное повторное открытие знаний
```

## Ветки, а не отдельные методологии

Пока следующие задачи считаются ветками трёх базовых практических сценариев:

```text
изменение интеграции
архитектурное изменение
замена технологии
миграция старой документации
миграция данных
смена провайдера
изменение безопасности или регуляторных требований
```

Они могут стать отдельными практическими сценариями позже, если повторные реальные применения покажут существенно другой порядок зависимостей.

## Правило

> **Новый практический сценарий нужен не потому, что задача иначе называется, а потому, что у неё действительно отличается структура зависимостей работы.**
