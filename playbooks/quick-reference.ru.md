# Краткая памятка по практическим сценариям

[Английская версия](quick-reference.md)

## Какой практический сценарий выбрать?

```text
СТАРТ
  │
  ├─ Это новая система или новая подсистема без существующей основы?
  │      └─ ДА → NEW SYSTEM
  │
  └─ НЕТ
      │
      ├─ Реальная система уже существует?
      │      └─ НЕТ → NEW SYSTEM
      │
      └─ ДА
          │
          ├─ Знания о текущем состоянии достаточно надёжны?
          │      └─ НЕТ → EXISTING SYSTEM
          │
          └─ ДА → CHANGE
```

## Новая система

Использовать, когда:

- создаётся новый продукт или сервис;
- создаётся новый плагин;
- появляется крупная новая подсистема;
- архитектура ещё не стабилизирована;
- восстанавливать существующее состояние не требуется.

Главный риск:

> начать проектировать зависимые детали раньше, чем определены ответственность и владение.

Начало: [`new-system.ru.md`](new-system.ru.md)

## Существующая система

Использовать, когда:

- система уже работает;
- документация отсутствует, устарела, разрознена или противоречива;
- код и наблюдаемое поведение надёжнее документации;
- требуется миграция старой документации;
- нужно разделить текущее и целевое состояние.

Главный риск:

> описать архитектуру, которую хотелось бы видеть, вместо той, которая реально существует.

Начало: [`existing-system.ru.md`](existing-system.ru.md)

## Изменение

Использовать, когда:

- уже существует статус `Stable` или достаточно надёжная базовая версия;
- меняется функция или бизнес-правило;
- добавляется или меняется интеграция;
- заменяется провайдер или технология;
- может измениться владение данными или граница системы;
- меняется архитектура.

Главный риск:

> принять системное изменение за локальную задачу реализации.

Начало: [`change.ru.md`](change.ru.md)

## Если есть сомнения

Если невозможно уверенно сказать, что базовая версия достоверна:

> начинай с **Существующая система**, пока подтверждения и владение не станут достаточно стабильными.

Ошибочно считать ненадёжную основу стабильной опаснее, чем выполнить короткий проход восстановления.
