## Decision Lifecycle

```text
Observed problem
→ example exploration and/or application evidence
→ proposal or direct decision candidate
→ validation
→ accepted decision
→ specification update
```

Synthetic examples may be used to explore a decision cheaply.

Real-world applications provide stronger evidence because the methodology must survive actual project constraints.

Use `proposals/` for ideas that are not yet accepted.

A methodology ADR should normally include:

```text
Context
Decision
Consequences
Evidence
Status
```

Do not create an ADR for editorial changes that do not alter methodology behavior.
