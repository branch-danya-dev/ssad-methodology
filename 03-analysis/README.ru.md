# 03 · Analysis

Этот раздел содержит **аналитический инструментарий SSAD**.

Если workflow отвечает на вопрос «что делать на работе», то analysis отвечает:

> **Как именно разбирать систему и принимать системные решения?**

## Основные конструкции

```text
BOUNDARIES
RESPONSIBILITIES
OWNERSHIP
BEHAVIOR
STATES
DATA
INTERFACES
INTEGRATIONS
FLOWS
TRUST
FAILURES
SYNTHESIS
```

Это не обязательные названия документов или директорий. Это аналитические вопросы, на которые система должна дать явные ответы.

## Пример

Для вопроса ownership недостаточно написать «Backend отвечает за доступ».

Нужно понять:

```text
Кто принимает решение?
Кто хранит каноническое состояние?
Кто может его изменить?
Кто потребляет результат?
Кто подтверждает корректность?
```

## Формат каждой темы

```text
Проблема
→ идея
→ вопросы
→ метод
→ результат
→ пример
→ схема
→ ошибки
→ проверка
```

Следующий раздел показывает, как результаты анализа превращаются в удобную систему знаний: [`04-knowledge-structure/`](../04-knowledge-structure/).
