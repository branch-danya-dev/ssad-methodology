# Сопровождение системных знаний

[Английская версия](maintenance.md)

SSAD рассматривает документацию как поддерживаемую модель системы.

## Причины для проверки

Сопровождение может потребоваться после изменения реализации, продуктового решения, API или схемы, изменения провайдера или платформы, инцидента, изменения безопасности, архитектурного решения, обнаруженного противоречия или устаревания подтверждений.

## Процесс

```text
Обнаружено изменение
→ найден канонический владелец
→ определена область влияния
→ обновлено каноническое знание
→ обновлены контекстные ссылки
→ обновлена трассируемость
→ проверены диаграммы / контракты / примеры
→ классифицированы оставшиеся неизвестные
→ восстановлен статус Stable
```

## Переработка устаревшей документации

До удаления или перестройки документации необходимо:

1. определить нового канонического владельца;
2. проверить старые документы на уникальные знания;
3. перенести уникальное содержание;
4. исправить ссылки;
5. удалить дублирование;
6. повторить проверку согласованности.

Нельзя удалять документацию только потому, что появилась более новая директория.

## Обнаружение расхождений

Полезные проверки включают неработающие ссылки, расхождение русской и английской версии, новый компонент без документации, технологию без владельца, дублирующий контракт, расхождение диаграммы и текста, расхождение схемы и документации и скрытые вопросы со статусом `OPEN`.
