# Pre-analysis checklist

Короткий маршрут для ситуации: **«Мне пришла новая задача. С чего начать?»**

## 1. Понять запрос

- Какую проблему пытаются решить?
- Кто инициатор изменения?
- Для кого меняется поведение?
- Как выглядит ожидаемый результат?
- Это новое поведение или изменение существующего?

## 2. Отделить потребность от предложенного решения

Если запрос звучит как «добавить endpoint», «сделать таблицу», «подключить Kafka», спроси:

- какую потребность решает это предложение;
- обязательно ли решение должно быть именно таким;
- какие ограничения уже известны;
- кто предложил реализацию и на каких предположениях она основана.

## 3. Найти первичные границы

- Какие компоненты или responsibility zones точно затронуты?
- Какие внешние системы участвуют?
- Какие данные проходят через изменение?
- Какие существующие процессы могут быть затронуты?

Не пытайся сразу доказать полный impact. На pre-analysis нужен **initial scope**, а не окончательная карта системы.

## 4. Найти участников

Кто может подтвердить:

- бизнес-цель;
- текущее поведение;
- архитектурные ограничения;
- внешние контракты;
- данные и ownership;
- эксплуатационные ограничения.

## 5. Зафиксировать неизвестное

Не маскируй неизвестные места предположениями.

Используй явный список:

```text
KNOWN
ASSUMED
OPEN
OUT OF SCOPE
```

## Минимальный результат

```text
Problem / goal
Initial scope
Known constraints
Affected actors/systems
Known facts
Assumptions
Open questions
Next participants
```

Если этого нет, задача ещё не готова к глубокому анализу.
