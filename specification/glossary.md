# SSAD Glossary

[Русская версия](glossary.ru.md)

| Term | Definition |
|---|---|
| Analytical Perspective | A meaningful view that answers a class of questions about responsibility, behavior, data, or boundaries |
| Canonical Owner | The primary location responsible for defining a material fact |
| Contextual Usage | A local restatement of enough information to explain how canonical knowledge is used |
| Knowledge Architecture | The ownership and relationship model of system knowledge |
| Analysis Workflow | The dependency-driven process used to discover and stabilize knowledge |
| Change Model | The process used to evolve knowledge when the system changes |
| Change Surface | The set of canonical owners, boundaries, contracts, data, and invariants affected by a change |
| Evidence | A source supporting a statement about current or intended behavior |
| System Synthesis | Cross-component knowledge assembled at the nearest common system level |
| Example | A synthetic or intentionally simplified system used to explain or explore SSAD; it is not implementation evidence |
| Application | A real project actually documented using SSAD and usable as practical methodology evidence |
| Baseline | Knowledge stable enough to be used as upstream input |
| Stable | Knowledge sufficiently cross-checked to act as canonical truth until evidence or the system changes |
| Steward | A role responsible for maintaining the documentation representation of knowledge |
