# Роли и сопровождение знаний

[Английская версия](roles-and-stewardship.md)

SSAD разделяет **владение решением** и **сопровождение документации**.

| Знание | Типичный владелец решения | Типичный сопровождающий документации |
|---|---|---|
| Бизнес-цель / политика | Владелец продукта / заинтересованная сторона / эксперт предметной области | Бизнес-аналитик / системный аналитик |
| Бизнес-правило | Владелец продукта или предметной области | Бизнес-аналитик / системный аналитик |
| Граница системы | Продуктовые и архитектурные участники | Системный аналитик / архитектор |
| Контракт API | Команда-владелец интерфейса | Системный аналитик / разработчики |
| Владение данными | Команда-владелец ответственности | Системный аналитик / архитектор / владелец данных |
| Реализация | Команда разработки | Разработчики |
| Проверка поведения | Продуктовая или системная команда | QA / системный аналитик / разработчики |
| Эксплуатационная политика | Эксплуатационная или платформенная команда | Ops / SRE / архитектор |

## Вклад ролей

- **Бизнес-аналитик** защищает бизнес-смысл, процессы, цели заинтересованных сторон и бизнес-правила.
- **Системный аналитик** защищает согласованность системы, её границы, контракты, владение данными, трассируемость и непрерывность между бизнес-смыслом и технической реализацией.
- **Разработчик** предоставляет подтверждения реализации и проверяет техническую реализуемость и фактическое поведение.
- **QA** проверяет наблюдаемое поведение и воспроизводимость критериев приёмки.
- **Архитектор** проверяет межсистемные границы и значимые архитектурные решения.
- **Владелец продукта / заинтересованная сторона** принимает продуктовые решения и подтверждает бизнес-смысл.

## Если бизнес-аналитика нет

Системный аналитик может сопровождать бизнес-документацию, но должен сохранять различие:

```text
бизнес-решение
≠
техническое проектное решение
```

Отсутствующее бизнес-решение следует подтверждать с владельцем продукта или предметной области, а не выводить из удобства технической реализации.
