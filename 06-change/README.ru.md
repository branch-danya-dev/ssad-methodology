# 06 · Change

Этот раздел посвящён анализу изменений в существующей системе.

## Главный вопрос

> Что реально затронет изменение и какие знания нужно открыть заново?

## Базовая модель

```text
CHANGE REQUEST
      ↓
INITIAL SCOPE
      ↓
AFFECTED RESPONSIBILITIES
      ↓
AFFECTED OWNERS
      ↓
BEHAVIOR / DATA / CONTRACTS / STATES
      ↓
DEPENDENCIES / INTEGRATIONS / TRUST
      ↓
REVIEW & IMPLEMENTATION
      ↓
VERIFICATION
      ↓
KNOWLEDGE UPDATE
```

## Что здесь изучается

- первичная область изменения;
- impact analysis;
- Change Surface как практический инструмент;
- поиск затронутых владельцев знания;
- совместимость контрактов и данных;
- переоткрытие ранее стабильного знания;
- стабилизация после реализации.

## Важный принцип

Изменение не должно начинаться с переписывания всех связанных документов.

Сначала определяется, **что действительно затронуто**, затем открываются только необходимые области знания.
