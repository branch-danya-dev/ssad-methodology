# 05 · Collaboration

[Русская версия](README.ru.md)

This section explains **how system knowledge is created, validated and changed together with the delivery team**.

SSAD does not treat documentation as a private analyst archive or a one-way handoff.

The collaboration loop is:

```text
KNOWLEDGE CONTRIBUTION
→ VALIDATION
→ DECISION RESOLUTION
→ IMPLEMENTATION / QA / OPERATIONS
→ FEEDBACK LOOP
↺
```

## Knowledge Contribution

[`knowledge-contribution/`](knowledge-contribution/)

Ask not only who to talk to, but what knowledge a participant can confirm, reject, constrain or enrich. SSAD explicitly distinguishes evidence from authority.

## Validation

[`validation/`](validation/)

The team validates claims about the system rather than documents as text. Different perspectives expose different classes of error.

## Decision Resolution

[`decision-resolution/`](decision-resolution/)

Conflicting answers are resolved through evidence, authority, mandatory constraints, alternatives, consequences and the correct decision owner — not by voting.

## Knowledge Feedback Loop

[`feedback-loop/`](feedback-loop/)

Implementation, QA and operations return new evidence into analysis and canonical system knowledge.

`02-workflow` explains **when collaboration happens**. This section explains **how knowledge moves between people and SSAD**.

> **System knowledge is not handed to the team as a finished artifact. It is created, validated and evolved with the team.**
